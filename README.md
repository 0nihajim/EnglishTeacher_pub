# English Teacher × Gemini Live

声で英会話を練習するアプリです。先生と全二重で話し、教わった表現は会話を止めずに
カードで画面に出ます。シーン会話、瞬間英作文、話し直しトレーニングに加え、
履歴から組み立てる「今日の復習」があります。

[heygen-com/liveavatar-gpt-live-demos](https://github.com/heygen-com/liveavatar-gpt-live-demos)
(MIT © 2026 HeyGen)を Gemini Live API に移植したものです。教える方向は逆にして、
日本語話者が英語を練習する形にしています。

## 動かす

Node.js 22.16以上を使います。

```bash
cp .env.example .env      # GEMINI_API_KEY を埋める(https://aistudio.google.com/apikey)
npm install
npm run dev               # http://127.0.0.1:5173
```

Cloudflare向けの実装は [公開手順](docs/cloudflare-setup.md) を参照してください。
1人用のAccess認証、D1へのスクリプト・ノート保存、R2への圧縮録音の14日保存、
履歴画面とローカル復習データの取り込みを追加しています。
公開に使う値(ホスト名・Account ID・メール・AccessのAUD・D1のID)は `wrangler.jsonc` の
`REPLACE_ME` を自分の値に置き換える形で入れます。埋め忘れは配信コマンドが名前を挙げて止めます。
音声・保存の実機確認は各自の環境で行ってください。
`main` への push で `.github/workflows/deploy.yml` が同じ配信を行います(リポジトリのSecretに
`CLOUDFLARE_API_TOKEN` が必要。自分で配信しないならこのワークフローは削除してよい)。

`npm run dev` はサーバー(:8787)とブラウザ側(:5173)を同時に上げます。ブラウザ側が
`/api` と `/ws` をサーバーへ中継するので、見えるオリジンは1つです。

API キーを入れる前に見た目だけ確かめたいときは、`npm run dev -w web` だけ上げて
`http://127.0.0.1:5173/?demo=card` か `?demo=targets` を開きます(会話中の画面まるごとは
`?demo=recast`、話し直しは `?demo=board`、`?demo=review`、`?demo=compare`、ボードは
`?demo=whiteboard` で実際に描けます)。

本番相当で動かすなら `npm run build` してから `npm start`。サーバーが `web/dist` も配ります。

## モード

「はじめる」の前に4つから選びます。シーン会話と瞬間英作文はシーンを1つ選んで始め、
話し直しは画像を1枚選んで始めます。ボードは何も選ばずに始めます。

- **シーン会話(正解つき)** … あなたが決めたシーンを先生が演じ、そこで使ってほしい表現の機会を
  作ります。使えたかどうかは舞台の上の帯に出ます(文字起こしの照合と、先生の判定の両方)。
  言い直しは「あなたの文 → 表現を使った文」のカードで出ます。途中経過は先生に聞けば画面に出ます。
  会話中の画面については下の「会話中の画面」を参照してください。
- **瞬間英作文** … 日本語の文が出たら、すぐ英語で言います。先生が判定して正解を示し、間違えた文は
  最後にもう一周します。結果は `data/results/<scene>.jsonl` に残り、次回は間違えた文が先に出ます。
- **話し直しトレーニング** … 旅行の写真、作っているアプリの画面、仕事の構成図など、自分の画像を
  1枚選び、それについて自分の英語で話します。狙うのは、言いたい内容を自分で選び、複数の文をつなげて
  説明する力です。1回 5〜8 分。下に詳しく。
- **ボード** … 舞台がホワイトボードになります。iPad のペンや指で描きながら、描いたものについて
  英語で話します。板が変わると1枚の静止画として先生に届き、先生はそれを見て質問し、言い直しを
  カードに出します。シーンも画像も要りません。下に詳しく。

シーンは `server/scenes/<id>.json` に1ファイルずつ書きます。表現は一度書けばシーン会話と
瞬間英作文の両方で使えます。同梱の `self-intro.json` と `it-standup.json` が見本です。

### 会話中の画面

会話中は、口を動かす時間と、自分の英語と正しい英語の差に気づく回数を増やす画面にしています。
読ませる量が増えると口が止まるので、文字は必要なときだけ出します。

- **番** … 舞台の中央に「先生が話しています / あなたの番 / 聞いています」を大きく出します。
  先生が話しているのは、先生の文字起こしが開いているか、先生の声が鳴っているあいだ。学習者の
  発話が閉じてから先生が動き出すまでが「聞いています」で、12秒返事が無ければ番を返します。
- **目標表現** … 舞台の上の帯に英語だけを並べ、使えたら点灯します。日本語の意味はチップを押した
  ときに1つだけ出します。
- **先生の一文** … 先生のターンが閉じてから、最後の一文だけを舞台の下に出します。話している最中は
  出しません。割り込みで切られた発話は出しません。
- **言い直し** … 消えた語に線、増えた語に色を付けたカードが出ます。自分では消えず、「もう一度言う」
  (手動の区切りならそのまま「話す」になります)か「あとで」、または話し始めたときに閉じます。
- **言い直しレール** … 閉じた言い直しは右の欄に積まれます。札は「いま舞台に・あとで・言ってみよう・
  言えた」で、どれでも「言ってみる」で再挑戦できます。挑戦したあとの発話を文字起こしで照合し、
  増えた語の7割を言えていれば「言えた」にします(目標表現の口にしたと同じ強さの根拠です)。
  × で閉じると舞台が全幅に戻り、操作列の右に残り件数の札だけ残ります。
- **字幕** … 既定では出しません。操作列の「字幕」で右の欄に出し、そのあいだレールは引っ込みます。
  まとめて読むのは指導ノート(画面下)と履歴です。
- **マイク** … 操作列の中央に大きく置き、自分の番は塗り、手動の区切りでは「話す」と「送信」に
  なります。輪が自分の声の大きさで広がります。

見た目は `npm run dev -w web` だけ上げて `http://127.0.0.1:5173/?demo=recast` で確かめられます
(帯・先生の一文・カード・レールが揃った状態が出ます)。

### 今日の復習

ホームの「今日の復習」から始めます。過去の瞬間英作文、話し直しの改善点、
シーン会話の訂正と目標表現を読み、期限の来た課題を一度に最大3つ選びます。
履歴がなければ、先に通常の練習をすると課題が集まります。ボードの言い直しは課題にしません。

復習では、まず答えを見ずに話します。間違えた場合は、自己修正のための問い、
部分ヒント、お手本の順で支援します。「お手本を見る」で先へ進むこともできます。
確認後に「隠して、もう一度話す」を押し、自分の文で再挑戦します。
「話す」→「送信」の手動操作で区切るので、考えている間に答えを出しません。
復習中も、あなたと先生の発話は「字幕」を押せば右の欄で読めます。指導ノートは復習の終了後に表示します。

結果は「自力で言えた・自分で直せた・ヒントで言えた・お手本の後に言えた・もう一度練習・
スキップ」を区別して `data/results/_reviews.jsonl` に保存します。
自力で成功すると次回まで1・3・7・14・30日と間隔を延ばし、自己修正や支援後の成功は翌日、
言えなかった課題とスキップは10分後から再び出題できます。これは初期のスケジュールで、
個人に最適な間隔を推定するものではありません。途中終了や聞き取り不明の発話は、
失敗として記録しません。

課題と予定は保存した履歴から再構築するので、ページ再読み込みやサーバー再起動をまたいで
残ります。現状はこのサーバーを使う学習者1人分の履歴です。
`GET /api/review/today` は答えを含まない計画を返し、
`POST /api/session/start` に `{ "mode": "review" }` を渡すと復習を開始します。
進行と保存は自動テストで確認していますが、実際の音声での指導品質は未検証です。

### 採点と指導

- **訂正の理由と表現の使い分け** … 目標表現以外の文法・語法も指導します。正しい英文への別案は
  誤りの訂正と区別し、自然な言い換えと使いどころ、コロケーションの型・意味・例文、
  自分の文を作る練習を必要に応じて添えます。
- **判定** … シーン会話の成功件数には、先生が文脈も含めて正しく使えたと判定した表現だけを
  数えます。瞬間英作文は模範解答との一致だけを求めず、意味が合う自然な別解も認めます。
- **話し直しの評価** … 1回目と2回目を「伝わりやすさ・文法・自然さ・表現の幅」の4軸で
  各5段階評価し、発話の引用と理由を表示します。根拠が足りない項目は保留にし、
  改善表現も単語の重なりだけでは成功としません。今回の発話に対するAI評価で、
  発音の採点や資格試験のスコア換算ではありません。実音声での評価精度は別途検証が必要です。
- **指導ノート** … カードが閉じた後も、画面下のノートで指導内容を見返せます。直近30件を
  このページ内で保持し、終了後も残します。次の接続成功時かページ再読み込みで消えます。
  瞬間英作文の指導内容と話し直しの評価・指導内容は、結果の JSONL にも記録します。

### シーンの定義

```json
{
  "id": "it-standup",
  "title": "IT系: 朝会で進捗を話す",
  "situation": "You are a teammate running a casual daily standup with the learner ...",
  "learnerRole": "バックエンド担当のエンジニア",
  "promptVoice": true,
  "targets": [
    {
      "term": "I'm working on",
      "meaning": "〜に取り組んでいる",
      "example": "I'm working on the login bug.",
      "variants": ["I am working on"]
    }
  ],
  "drills": [
    {
      "ja": "今ログインのバグに取り組んでいます。",
      "en": "I'm working on the login bug.",
      "accept": ["I am working on the login bug."]
    }
  ]
}
```

- `targets` がシーン会話の「正解」。`term` と `meaning` は必須、`reading` と `example` は任意。
  `variants` は同じ表現と見なす別形で、文字起こしの照合に使います。
- `drills` が瞬間英作文の問題。省くと `targets` の「意味 → 表現」を問題にします。`accept` は正解扱いの別解。
- `promptVoice` を false にすると、先生は日本語文を読み上げず画面だけで出題します。
  `drillLimitMs` は1問の制限時間(既定 8000)。
- 壊れたファイルは起動ログに名前と理由が出て、そのシーンだけ飛ばされます。

### 話し直しトレーニング

1回の流れは5段階で、段階は舞台の左の板に出ます。板には選んだ画像と、その段階で見てよい
文字(観点 → キーワード → 追加の質問)だけが載ります。

1. **画像を選ぶ。** 写真かスクリーンショットを1枚(クリック、ドロップ、貼り付け)。ブラウザで
   長辺 1280px に縮めてから送るので、写真がそのまま上がることはありません。板に話す観点が
   出ます: これは何? / 何をした? / 困ったこと / 次にすること。
2. **30〜60秒、自分の英語で説明する。** 「話す」を押して話し、言い終えたら「送信」。先生は送信まで
   待ち、途中で訂正しません。詰まったら「ヒント」を押すと、先生が次に言えそうな 2〜5 語のかたまり
   (直前に日本語で言った語があればその英語)を1つだけ言ってカードに出し、また黙ります。
3. **改善点を1〜2個だけ確認する。** 送信すると、説明の録音と画像を Gemini Flash に渡して整理します
   (伝わった要点、改善点、2回目のためのキーワード、追加の質問)。先生は「聞きました、少し待って」と
   一言だけ言い、整理が届いたら改善点を「あなたの文 → 自然な言い方」で声とカードで示します。
   本人の意図と語彙のレベルは変えません。
4. **同じ内容をもう一度話す。** 改善点のカードが閉じ、板には画像とキーワードだけが残ります。
   先生は最後まで聞き、良くなった点を一言、直すなら一点だけ言います。
5. **追加の質問に答える。** 例えば開発中の画面なら "What will you work on next?"。答えたら先生が締め、
   舞台に比較が出ます: 1回目と2回目の字幕・語数・秒数・伝わった要点、改善点が2回目で使えたか、
   Flash の一言。「聞く」でそれぞれの録音を聞き比べられます(録音はブラウザの中だけ。サーバーには
   残しません)。

このモードは発話の区切りが手動に固定され、無音のときの先生の声かけも止めています。考えている
時間を奪わないためです。

結果は `data/results/retell.jsonl` に1セッション1行で残ります(要点、ヒントの数、改善点を
2回目で使えたか、追加の質問と答え、4軸の評価と指導内容)。長期の振り返りでは、伝えられた要点、
必要だったヒント、後日別の画像でも同じことができるかを確認します。最後の1つはまだ手作業で、
別の画像で始めて `retell.jsonl` の行を見比べる形です。

進行はアプリが持ちます(`server/src/modes/retell.ts`)。段階を進める合図は「学習者の送信」
「先生のターンが閉じた」「Flash の整理が返った」の3つだけで、モデルのツール呼び出しには
頼っていません。Flash の整理が失敗したとき(タイムアウト 25 秒)は、先生が自分の聞いた内容から
改善点を選び、板は観点のまま2回目に進みます。

### ボード

舞台の全面がホワイトボードになります。描いたものについて英語で話し、先生は板を見て質問します。
描く題材は自由です(作っているものの構成、今日の段取り、朝の道順)。いまは自由会話だけで、
お題を出す形の練習はまだありません。

- **描く** … Apple Pencil でも指でも描けます。手のひらが線になるなら左上の「ペンのみ」を押します。
  道具は戻す・全消去・ペンのみの3つで、色と太さはまだ1種類です。
- **先生に見せる** … 板が変わって 600ms 静止したら、1枚の静止画(長辺 768px の白地 JPEG)として
  送ります。上限は1枚/秒で、話し始めた瞬間に未送信の変化があれば静止を待たずに送るので、
  先生は答えるときに最新の板を見ています。送った枚数は左上に出ます。
- **送らないとき** … 板が変わっていなければ1枚も送りません。常時 1fps にすると10分で約155Kトークン
  になり文脈窓を圧縮で削り続けるので、変化したときだけにしています(10分で数十枚、$0.05前後)。
- **言い直し** … シーン会話と同じカードとレールを使います。その場で直して言い直すところまでが
  ボードの練習なので、訂正は記録せず、「今日の復習」の課題にもしません(画面下の指導ノートでは
  そのセッションのあいだ読み返せます)。
- **区切り** … 自動と手動のどちらも選べます。既定は自動で、両手が板に行くのでボタンを押さずに
  話せます。手動にすると「話す」と「送信」の直前に板を送ります。

先生は板に描けません。指す必要があるときはラベルか位置で言います(the box on the left)。
振る舞いは `server/prompts/whiteboard.md`、板の間引きと書き出しは `shared/strokes.ts`
(テストは server 側)、描画は `web/src/board.ts` です。

## 発話の区切り

「はじめる」の前に、自分の発話の終わりを誰が決めるかを選びます。選択はブラウザに残ります。
話し直しトレーニングでは手動に固定されます。

- **自動** … Gemini の発話区間検出(VAD)。話し終えて黙ると先生が答えます。無音の長さは
  `.env` の `GEMINI_VAD_SILENCE_MS` で調整します。
- **手動(送信ボタン)** … マイクのボタンが「話す」と「送信」になります。「話す」を押して話し、
  言い終えたら「送信」。先生は送信まで待ち、途中の間(ま)で答え始めません。スペースキーでも
  切り替えられます。先生が話している最中に「話す」を押すと割り込みになります。

手動は Gemini Live の VAD を切って(`automaticActivityDetection.disabled`)、ボタンを
`activityStart` / `activityEnd` に写しています。マイクの音声はどちらの方式でもブラウザから
流れ続けますが、手動では「話す」から「送信」までの分だけを先生に渡し、外は捨てます。
先生の声のエコーや、考えている間の物音を先生に聞かせないためです。

## 学習者の言語

先生は英語と日本語しか聞かない・話さない前提です(`.env` の `GEMINI_INPUT_LANGUAGES`、
既定 `en-US,ja-JP`)。初級者の英語が別の言語として聞き取られ、先生がその言語で応じる事故を
2つの層で塞いでいます。

- **system instruction** … 「学習者は英語と日本語しか話さない。別の言語に聞こえてもそのどちらかとして
  扱い、第三の言語を聞かず・答えず・言及しない」。公式ドキュメントがネイティブ音声モデルの
  言語制限の手段として挙げているのはこれです。
- **文字起こしのヒント** … `inputAudioTranscription.languageCodes` に同じコードを渡します。字幕
  (学習者の行)の言語の取り違えを減らします。SDK の型にはありますが公式ドキュメントに記載が無く、
  上流が拒めばサーバーがヒントを外して繋ぎ直し、ログに `言語ヒント(...)を外して接続し直す` と出ます。

## 先生を変える

- 人格 … `server/prompts/instructions.md`
- シーン会話・瞬間英作文の進め方 … `server/prompts/scene.md` と `server/prompts/drill.md`
- 話し直しの進め方 … `server/prompts/retell.md`(先生の振る舞い)と `server/prompts/retell-review.md`
  (整理役の Flash に渡す方針: 何を直し、何を流すか、キーワードと質問の作り方)。話す観点は
  `server/src/prompts.ts` の `RETELL_PROMPTS`
- ボードの進め方 … `server/prompts/whiteboard.md`
- 練習する中身(表現と問題) … `server/scenes/*.json`
- 声 … `.env` の `GEMINI_VOICE`(Kore, Puck, Charon, Fenrir, Aoede …)
- 整理役のモデル … `.env` の `GEMINI_FLASH_MODEL`(既定 `gemini-3.8-flash`)
- 発話の切れ目の感度 … `.env` の `GEMINI_VAD_SILENCE_MS`(既定 1500。学習者がこれだけ黙ると
  「言い終えた」と判定される)と `GEMINI_VAD_START_SENSITIVITY`(LOW/HIGH。小声で発話が
  開かないときだけ HIGH に)。どちらも区切りが「自動」のときだけ効く
- 学習者の言語 … `.env` の `GEMINI_INPUT_LANGUAGES`(既定 `en-US,ja-JP`。空にすると自動判定)

`server/src/prompts.ts` の `TOOL_DIRECTIVE` はカードを出すための配線です。書き換えると
カードが出なくなったり、先生が「画面を見てください」と言い出したりします。


## 移植で分かったこと

**委譲の段が丸ごと消えます。** GPT-Live 版はライブ音声モデルがツールを持たず、画面に
何か出したいときは裏の Responses モデルにターンを渡し、返ってきた言葉をライブ側に
注入していました。Gemini Live はライブモデル自身が function calling を持つので、
`gptlive.ts` と `prompts.ts` の委譲プロンプトが要りません。

**割り込み判定も消えます。** デモは相槌と本当の割り込みを区別するために600ms見張って
音声の途切れ具合で決めていました。Gemini は `serverContent.interrupted` を明示的に
送るので、受けて再生キューを捨てるだけです。

**代わりに音声の再生が増えます。** アバターの声は LiveKit が運んでいたので、ブラウザは
`<audio>` に流すだけでした。顔を捨てた分、24kHz の生 PCM を自分で並べる仕事が
`web/src/audioPlayback.ts` に来ています。移植でいちばん増えた部分です。

**時間制限の扱いが要ります。** 音声のみのセッションは15分、1接続は約10分で切れます。
`contextWindowCompression`(15分の壁を外す)と `sessionResumption`(接続を張り替えても
会話を続ける)の両方を入れてあります。張り替えのとき音声が1秒ほど途切れ、字幕に
「接続を張り替えました」と出ます。

**カードは黙って出させます。** `show_term_card` は `behavior: NON_BLOCKING` で登録し、
結果を `scheduling: SILENT` で返します。これでモデルは喋りを止めずにカードを出し、
「いまカードを出しますね」と言いません。舞台をまるごと使うまとめ(`show_progress`)だけは
`WHEN_IDLE` で、いま話していることを終えてから一覧を読み上げます。

## 実通話で分かったこと

最初の実通話で「先生の声が二重に重なる」「学習者が言い終える前に先生が答える」が出ました。
原因はどれも、この API の性質とコードの前提が食い違っていたことです。

**音声は実時間で届きません。** Gemini は1ターン分の音声を数秒でまとめて送ってきます
(SDK の注釈: "generated as quickly as possible, and not in real time")。ブラウザの
再生キューは発話の長さぶん積み上がるのが正常で、「溜まりすぎ」を理由に今へ寄せると
鳴っている途中の声に次の声が重なります。サーバー側で「先生がいつ喋り終わるか」を知るには、
受信時刻ではなく届いた PCM の長さを積み上げます(`server/src/silence.ts`)。

**進行の差し込みは生成に割り込みます。** `sendClientContent` は `turnComplete` の真偽に
関係なく「生成中なら割り込む」と SDK に明記されています。先生のターンが閉じてから送り、
学習者の番を奪いたくない指示(シーン会話の舵取り)は `turnComplete: false` で文脈に追記だけして、
学習者の次の発話と一緒に処理させます。

**VAD の既定は敏感です。** 開始・終了とも HIGH で、初級者の文中の息継ぎで「言い終えた」に
なります。終了側を LOW、無音 1.5 秒にしてあります(`.env` で調整)。

**setupComplete は connect() が返る前に届きます。** SDK はキューしたメッセージを
`connect()` の resolve 直前に `onmessage` へ流すので、そのハンドラの中では自分の
`session` 変数がまだ入っていません。接続直後にやること(挨拶)は `connect()` の後に
置いてあります。以前はここで挨拶が黙って落ちていました。

## 分かっている残件

- **実通話の確認はまだ浅いです。** 上の4点はコード上で確定した原因で、直してあります。
  実通話で見るべき点: 挨拶が `ready` の直後に来ること、長い発話が1本の声で鳴ること、
  文中で1秒止まっても先生が待つこと。小声で発話が開かなければ
  `GEMINI_VAD_START_SENSITIVITY=HIGH`。スピーカー再生で字幕の「あなた」行に先生の
  言葉が混ざるなら、エコーキャンセルが効いていない環境なので、ヘッドホンを使ってください。
- **認証がありません。** ブラウザから叩けるものは誰でも叩けます。外に出すなら
  `POST /api/session/start` にログインを要求し、WebSocket の upgrade を `/start` が
  発行する短命チケットで検証してください。塞がないと、URL を知っている誰でも
  セッションを開けて課金はこの API キーに乗ります。詳しくは `server/src/index.ts` 冒頭。
  API キー自体はサーバーに留まりブラウザには渡りません。
- **発音の採点はありません。** Gemini Live のドキュメントに音素レベルの採点はなく、
  やるなら別の層が必要です。
- 結果から「今日の復習」の出題と復習間隔を決めます。アカウント別の履歴、
  端末間の同期、長期間の成長グラフはありません。
- シーン会話と瞬間英作文も実通話は未確認です。特に瞬間英作文は、先生が `drill_result` を
  呼び忘れたときの催促(無音の見張り経由)と、読み上げが終わってから時計が動く前提を、
  `GEMINI_DEBUG=1` のログで確かめてください。
- 発話の区切り「手動」と言語ヒントも実通話は未確認です。手動で見るべき点: 「送信」を押すまで
  先生が答えないこと、「送信」の直後に答え始めること(`GEMINI_DEBUG=1` で `→ activityEnd`
  の後に音声が来る)、先生の発話中に「話す」を押すと割り込めること。言語ヒントは、接続ログに
  `言語ヒント(...)を外して接続し直す` が出たら上流が受け付けていないということで、その場合は
  system instruction の制限だけで動いています。
- **話し直しトレーニングも実通話は未確認です。** 進行の状態機械と Flash の応答の整形はテストで
  固めてありますが、上流との接点は4つ確かめる必要があります。
  (1) 先生が画像を見ているか。挨拶で画像の中身を一言で言うはずで、「見えない」と言うなら
  `.env` の `GEMINI_IMAGE_VIA=content` に切り替えて試してください(既定の `realtime` は公式
  ドキュメントが画像に使っている `sendRealtimeInput` の video、`content` は挨拶と同じ
  clientContent の inlineData で、順序は確実だが Live の公式ドキュメントには載っていません)。
  (2) 「話す」を押したままの「ヒント」で先生が短く答え、そのまま続きを聞くこと(発話が開いている
  間の clientContent は未確認)。(3) 1回目の送信のあと、先生が講評を始めずに一言で待つこと
  (`retell.md` の指示。始めてしまうなら、アプリの講評と二重になります)。(4) Flash の整理が返る
  こと。`GEMINI_DEBUG=1` で `Flash 応答 …s` が出ます。`thinkingLevel` を拒まれたときは外して
  一度やり直します。整理が 25 秒で返らないと先生に任せる経路に落ちます。
  なお「音声+映像のセッションは2分」という上限は圧縮なしのときのもので、ここは
  `contextWindowCompression` を入れてあります。もし送信から2分前後で切れるなら、それが疑わしいです。
- **ボードは Phase 1 です。実通話と iPad 実機は未確認です。** 描画・間引き・フレームの検査は
  テストとブラウザ(マウス操作)で確かめてありますが、上流と実機は次の4点が未確認です。
  (1) 長辺 768px で手書きが読めるか。読めなければ `web/src/board.ts` の `FRAME_LONG_SIDE` を
  1024(516 トークン)に上げます。先生が挨拶のあと板の中身に触れるかで判断します。
  (2) 区切りが「手動」(VAD 無効)のあいだも video フレームが処理されるか。ドキュメントに記載が
  無く、処理されないならボードは自動固定にします。`GEMINI_DEBUG=1` で `板のフレーム #n → 先生`
  のあと先生が板に触れるかを見ます。(3) iPad Safari の音声。`getUserMedia` は HTTPS が要るので
  手元の 127.0.0.1 は iPad から使えません。本番(Access 越し)か、`vite --host` と mkcert で
  LAN に HTTPS を立てて試します。(4) Apple Pencil と手のひら。指も描ける既定のままで手が線に
  なるなら「ペンのみ」で塞げるかを見ます。
  Phase 1 の範囲外: お題を出す練習(「聞いて描く」)、色と太さ、圧力、最終の板の保存、
  先生が板を指す目印。クラウド版(Cloudflare)は板のフレームを中継するので、iPad からは
  本番(Access 越し、HTTPS)で試せます。

## 原価の目安

音声入力 $3.00/1M(実効 約$0.005/分)、音声出力 $12.00/1M(実効 約$0.018/分)。
学習者と先生が半々に話す10分のレッスンで約$0.14です。無料枠がありますが、無料枠の
データは製品改善に使われるので実運用は有料枠が前提になります。音声出力には SynthID の
電子透かしが入ります。

話し直しでは Flash の呼び出しが1セッションに2回加わります。1回は画像(縮めた1枚で数百〜
1,000 トークン強)と録音(32 トークン/秒、1分で 1,920 トークン)と方針の文で、合わせても
数千トークンです。Live 側に渡す画像も1枚ぶんなので、10 分のレッスンの原価は上の見積もりから
ほとんど動きません。

ボードでは板のフレームが加わります。長辺 768px で1枚 258 トークン、変化したときだけ送るので
10分で数十枚、$0.05 前後です(常時 1fps なら600枚=約155Kトークンで、原価も文脈窓も別の話に
なります)。10分のレッスンで $0.19 前後が見込みです。
