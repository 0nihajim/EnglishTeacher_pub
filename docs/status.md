# 未確認の点

[README](../README.md) に戻る。

手元のサーバー版は自動テストと型検査を通していますが、実際の音声でのやり取りは各自の環境で
確かめる必要があります。以下は作者が確かめていない点です。

## 認証がありません(最優先)

手元のサーバー版(`npm run dev` / `npm start`)には認証がありません。ブラウザから叩けるものは
誰でも叩けます。URL を知っている誰でもセッションを開けて、課金はあなたの API キーに乗ります。
外に出すなら次のどちらかにしてください。

- Cloudflare 版を使う([公開手順](cloudflare-setup.md))。1人用の Access 認証が付きます。
- サーバー版を自分で塞ぐ。`POST /api/session/start` にログインを要求し、WebSocket の upgrade を
  `/start` が発行する短命チケットで検証します。詳しくは `server/src/index.ts` 冒頭。

API キー自体はサーバーに留まり、ブラウザには渡りません。

## 実通話で見る点

- 挨拶が `ready` の直後に来ること、長い発話が1本の声で鳴ること、文中で1秒止まっても先生が待つこと。
- 小声で発話が開かなければ `GEMINI_VAD_START_SENSITIVITY=HIGH`。
- スピーカー再生で字幕の「あなた」行に先生の言葉が混ざるなら、エコーキャンセルが効いていない
  環境です。ヘッドホンを使ってください。

## モードごとの未確認事項

**シーン会話・瞬間英作文** … 瞬間英作文は、先生が `drill_result` を呼び忘れたときの催促(無音の
見張り経由)と、読み上げが終わってから時計が動く前提を、`GEMINI_DEBUG=1` のログで確かめてください。

**発話の区切り「手動」と言語ヒント** … 手動では「送信」を押すまで先生が答えないこと、「送信」の
直後に答え始めること(`GEMINI_DEBUG=1` で `→ activityEnd` の後に音声が来る)、先生の発話中に
「話す」を押すと割り込めること。言語ヒントは、接続ログに `言語ヒント(...)を外して接続し直す` が
出たら上流が受け付けていないということで、その場合は system instruction の制限だけで動いています。

**話し直しトレーニング** … 進行の状態機械と Flash の応答の整形はテストで固めてありますが、
上流との接点は4つ確かめる必要があります。

1. 先生が画像を見ているか。挨拶で画像の中身を一言で言うはずで、「見えない」と言うなら `.env` の
   `GEMINI_IMAGE_VIA=content` に切り替えて試してください(既定の `realtime` は公式ドキュメントが
   画像に使っている `sendRealtimeInput` の video、`content` は挨拶と同じ clientContent の
   inlineData で、順序は確実だが Live の公式ドキュメントには載っていません)。
2. 「話す」を押したままの「ヒント」で先生が短く答え、そのまま続きを聞くこと(発話が開いている
   間の clientContent は未確認)。
3. 1回目の送信のあと、先生が講評を始めずに一言で待つこと(`retell.md` の指示。始めてしまうなら、
   アプリの講評と二重になります)。
4. Flash の整理が返ること。`GEMINI_DEBUG=1` で `Flash 応答 …s` が出ます。`thinkingLevel` を
   拒まれたときは外して一度やり直します。整理が 25 秒で返らないと先生に任せる経路に落ちます。

なお「音声+映像のセッションは2分」という上限は圧縮なしのときのもので、ここは
`contextWindowCompression` を入れてあります。もし送信から2分前後で切れるなら、それが疑わしいです。

**ボード(Phase 1)** … 描画・間引き・フレームの検査はテストとブラウザ(マウス操作)で確かめて
ありますが、上流と実機は4点が未確認です。

1. 長辺 768px で手書きが読めるか。読めなければ `web/src/board.ts` の `FRAME_LONG_SIDE` を
   1024(516 トークン)に上げます。先生が挨拶のあと板の中身に触れるかで判断します。
2. 区切りが「手動」(VAD 無効)のあいだも video フレームが処理されるか。ドキュメントに記載が無く、
   処理されないならボードは自動固定にします。`GEMINI_DEBUG=1` で `板のフレーム #n → 先生` のあと
   先生が板に触れるかを見ます。
3. iPad Safari の音声。`getUserMedia` は HTTPS が要るので手元の 127.0.0.1 は iPad から使えません。
   Cloudflare 版(Access 越し)か、`vite --host` と mkcert で LAN に HTTPS を立てて試します。
4. Apple Pencil と手のひら。指も描ける既定のままで手が線になるなら「ペンのみ」で塞げるかを見ます。

Phase 1 の範囲外: お題を出す練習(「聞いて描く」)、色と太さ、圧力、最終の板の保存、先生が板を
指す目印。

## そもそも無い機能

- **発音の採点** … Gemini Live のドキュメントに音素レベルの採点はなく、やるなら別の層が必要です。
- **アカウント別の履歴、端末間の同期、長期間の成長グラフ** … ありません。結果は1人分の履歴として
  「今日の復習」の出題と復習間隔を決めるためだけに使います。
